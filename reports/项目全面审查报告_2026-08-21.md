## 二、严重问题（建议优先修复）

### S1. 注册后数据割裂：同一 device_id 变成两行用户记录 ⚠️ 最重要

**位置**: [main.py:355](cine/main.py) `_resolve_user_id` + [main.py:588](cine/main.py) `api_register`

流程：游客用 device_id=dabc 产生 guest 用户行（id=1）→ 聊天/人格/行为信号都挂在 id=1 下 → 用户在**同一浏览器**注册，`api_register` 新建 id=2（带 phone，**device_id 也写成 dabc**），把 id=1 的聊天和收藏**搬走** → 于是 users 表出现两行 device_id=dabc。

后果：
- 之后 `_resolve_user_id(dabc)` 的 `SELECT id FROM users WHERE device_id=?` 无 ORDER BY，`fetchone()` 永远先取到旧的 id=1（游客行）。聊天继续写进 id=1，但账号页/收藏走 token→id=2。
- **新聊天记录在账号历史里不显示**（历史读 id=2 的 chats，新消息写 id=1 的 chats）。
- 人格测试存到 id=1，`/api/personality/profile` 用 token 读 id=2 → 404，只能靠 localStorage 兜底，**服务端画像在注册后失效**。
- B4 隐式画像断裂：`/api/feedback` 把信号写到 id=2，`api_chat` 里 `_implicit_profile` 却读 id=1 的信号 → **注册用户的行为信号永远为空**。

这正踩在最主要的引导流程（"游客 → 注册合并"）上，建议演示前修复。

### S2. 每打开一次电影详情页，后端解析一遍 30MB CSV

**位置**: [data.py:216](cine/data.py) `top_comments`

`api_movie` 对每部核心片调用 `top_comments`，函数内每次 `pd.read_csv(data/movie_comments.csv)`（30MB，**实测 0.67s**）再过滤。即每次详情页请求多花约 0.7s，且并发时多请求同时解析 30MB。应当启动时加载一次缓存到内存（88,169 行，内存代价小），或预建 cid→comment 的查询表。

### S3. FTS sqlite 连接跨线程共用

**位置**: [data.py:51](cine/data.py)

`_fts = sqlite3.connect(FTS_DB, check_same_thread=False)` 在启动时打开一次，FastAPI 的同步端点跑在线程池里，`search_fts` / `top_comments` 从多个线程同时操作这一个连接。SQLite 单连接并发读不保证安全，可能出现 `Recursive use of cursors not allowed`、脏读或偶发 `database is locked`。建议每请求新建只读连接，或用连接池。

### S4. 聊天会话无归属校验（越权读写他人会话）

**位置**: [main.py:292](cine/main.py) `_load_conversation_history` + [main.py:334](cine/main.py) `_save_conversation_message`

`/api/chat` 完全信任客户端传来的 `conversation_id`，不校验该会话是否属于当前 device_id/user。传入任意整数即可把别人的会话历史喂给 LLM 上下文（读到对方偏好），并向对方会话追加消息。演示期影响有限，但这是明确的授权漏洞，修复成本低（查 conversations 时加 `AND user_id=?`）。

### S5. 开场动画蓄力时音效每 16ms 重触发

**位置**: [BootScene.tsx:73](cine/web/src/scenes/BootScene.tsx) + [BootScene.tsx:81](cine/web/src/scenes/BootScene.tsx)

`useProjectorSound()` 每次渲染都返回新的 `play` 函数（未 useCallback），而蓄力 effect 依赖数组里有 `sound`。蓄力时每 16ms `setCharge` 触发一次重渲染 → effect 清理并重跑 → 每次都 `sound('gear')`。结果是按住期间齿轮声以 ~60 次/秒连续炸响（听感是刺耳噪声），并伴随 interval 反复重建。修复：用 `useCallback` 包住 `play`，或从依赖数组去掉 `sound`。

## 三、中等问题

### M1. `/api/movies` 搜索分支忽略 genre 筛选
[main.py:97](cine/main.py)：`q` 分支只做标题/类型/导演/演员包含匹配，随后的公共过滤只检查 region/year/dim，**没检查 genre**。列表页"搜索 + 再选类型"时类型不生效。

### M2. 短信码登录未注册手机号返回假 token
[main.py:610](cine/main.py)：`api_login` 用 code 时只校验验证码，不校验手机号是否注册过；未注册手机号 + 固定验证码 246810 → `row` 为 None → `_token(None, phone)` 照样生成 token、`UPDATE` 空操作，接口返回 `{"token": 任意值, "user_id": null}`。前端拿到无效 token 后 401 → 被迫切游客。应返回 400 或自动注册。（注：前端验证码 Tab 走的是 register，此 bug 仅直接调 API 可达。）

### M3. 注册合并遗漏人格/行为信号/会话
[main.py:588](cine/main.py)：合并逻辑只搬 `chats` 和 `favorites`，`user_personality`、`user_signals`、`conversations` 全部留在旧游客行。即使 S1 修好，注册后人格与隐式画像仍不同步。建议合并时一并迁移这三张表。

### M4. echarts 依赖与 EChart 组件完全闲置
[EChart.tsx](cine/web/src/components/EChart.tsx) 没有任何页面引用，`package.json` 里的 `echarts@6` 是死依赖。这正对应赛前报告指出的"数据可视化不足"——骨架都在，只是没接线。

### M5. 三套前端并存 + dist 缺失即启动崩溃
[main.py:24](cine/main.py)：`static/` 与 `static_legacy/` 内容**逐字节相同**（重复备份），且注释说"旧 static 备份于 static_legacy"，但代码里 `WEB_DIST/index.html` 不存在时 `STATIC_DIR` 仍是 `web/dist`（不存在），`StaticFiles` 启动即抛 `RuntimeError`——**并没有真正的 fallback**。三套目录建议只留一套。

## 四、安全隐患（演示项目可接受，需知晓边界）

| 项 | 位置 | 说明 |
|---|---|---|
| 固定验证码 246810 且接口明文返回 | main.py:554 | 任何手机号都可被他人"注册/登录"，账号体系无实际安全性 |
| 密码 SHA-256 无盐 | main.py:581/616 | 彩虹表可破；建议 bcrypt/argon2 |
| token 走 URL query | 多个端点 | 会进访问日志/浏览器历史；建议 header |
| CORS `*` | main.py:22 | 全开放，配合 localStorage token 放大风险面 |
| `/api/auth/sms` 无速率限制 | main.py:550 | 可被脚本刷 |
| `_token` 用 MD5 | main.py:88 | 弱散列，含时间戳尚可 |
| `@app.on_event("startup")` | main.py:32 | 已废弃，建议 lifespan |

这些都是"演示期"有意为之的取舍，README 也有注明；但如果赛后要上线，前 4 项必须重做。

## 六、前端专项

- **ext 电影降级完整**：详情页对无 DNA/情绪/相似片的库外片通过 `hasDna`、可选链逐处降级，不会白屏，设计良好。

## 七、代码卫生与维护性

1. **无版本控制**：项目根不是 git 仓库，30MB+ 数据、构建产物、临时脚本全部无法回滚。赛前改坏的恢复成本极高，强烈建议至少建 git 并做快照（记忆里也提过"建议快照"）。
2. **根目录堆积**：`_tmp_*.py`（11 个）、`_shots/`、`__pycache__/`、`logs/` 多个 build_llm.log 累积 1MB+。`_tmp_` 是一次性调试脚本，可清理。
3. **`cine/web/README.md`** 还是 Vite 默认模板，未定制。
4. **`cine/__pycache__/` 与根 `__pycache__/`** 都在。
5. **`cine/data/*.db`、`server.log`** 是运行产物落在包目录内（*.db 已被 gitignore，但 server.log 会进版本库）。
6. **未用 import**：`main.py` 的 `Query`；`STATIC_DIR`/`WEB_DIST` 两变量同值。
