## 3. 功能规格要点（逐页）

### 3.1 首页 / 列表页
- 推荐固定只推 590 高分库（B3：用户未指定时绝不推库外片）。
- 卡片：真实海报缩略图 + 片名 + 年份 + 豆瓣评分 + DNA 顶维角标（如"演技 9.1"）。
- 文案用真实数字：590 部高分电影 × 88,169 短评 + 29,256 长评 ≈ 11.7 万条真实评论（已拍板）。
- 筛选：region（华语/欧美/日本/韩国）+ 类型 + 年份区间 + 评分区间 + DNA 维度排序。
- 离线/弱网不依赖任何外部请求（数据全部本地）。

### 3.2 详情页
- 主信息区：海报原图、片名/年份/地区/类型/导演/编剧/主演/片长/语言/评分/评分人数。
- **DNA 雷达**：五维分数 + 命中证据条数 n + 置信档角标（样本不足显示"样本较少"）。
- **摘录区（差异化核心）**：
  - up1 好评顶流 / dn1 差评顶流：评论原文 + votes 票数 + 星级 + 作者名。
  - 署名规则（B1）：摘录作者显示「豆瓣用户 @真实昵称」，不放主页链接；金句/长评 excerpt 统一署名「豆瓣影迷」。
  - **无剧透模式**（A6）：摘录区整体标注"可能含剧透"并默认收起，用户可展开。
- 相似片：similarity.json top8，点击跳转。
- 统计：短评数 / 长评数 / votes 合计 / useful 合计。
- **P2 追加**：brief 精炼简介、tags 标签（mood≤3 + scene≤2，带证据 tooltip）、warn 避雷（≤30 字 + 要点 + 证据数）、egg 冷知识（标注来源 rid）、金句区（citation + useful + 署名"豆瓣影迷"）。

### 3.3 聊天页（核心交互）
- 能力：① 推荐（"来部催泪的日本动画"）② 问答（"霸王别姬讲什么"）③ 举证检索（"哪部片有'陀螺'梗"）。
- **防幻觉铁律**：LLM 只负责组织语言，事实/引用全部由程序从 enriched 卡片 + FTS 证据喂入；引用必须带真实评论原文 + votes 背书 + 出处（差异化核心，已拍板）。
- 两档模式：
  - **联网模式（P2，需 key）**：意图解析后程序检索数据 → 组装上下文 → LLM 润色回复。
  - **离线模式（P1，无 key 时即此档）**：规则意图识别 + DNA/相似片规则推荐 + FTS 证据原文引用；页面显式标注"离线模式"（B4）。
- 对话侧栏可展示引用卡片（评论原文 + 电影名 + votes），点击直达详情页。

### 3.4 账号系统（B2 / C4 已拍板）
- 三入口：手机验证码、密码、游客。
- 游客：首次访问发 `device_id` 虚账号，收藏/聊天记录落库；注册时按 device_id 合并历史。
- 演示期 SMS 验证码：固定验证码或打印到服务端日志（不上真短信通道）。
- 技术：本地 SQLite 真后端（FastAPI），密码哈希存储；上线期迁云（见 §5）。

> **安全说明（演示期）**：验证码固定为 246810（打印到服务端日志），密码用 SHA256 存储，
> token 用 MD5 生成。上线期迁云数据库 + 真短信通道 + bcrypt 密码哈希 + 随机 token。

## 4. 技术架构（本地 demo，A2 已拍板）

```
浏览器（无构建 SPA）
   │  HTTP/JSON
   ▼
FastAPI（anaconda python，单进程）
   ├── /static      前端静态文件
   ├── /api/*       业务接口（见 §6）
   ├── 检索层        FTS5（comments_fts.db 只读）+ title 模糊
   ├── 推荐层        DNA + similarity.json（规则，毫秒级）
   ├── 聊天层        意图规则 → 数据组装 → LLM(可选) → 降级
   └── 账号层        SQLite（users / favorites / chats）
```

**技术选型（推荐，待确认）**：
- 前端：**原生 HTML/CSS/JS 无构建 SPA**（理由：零 node 依赖、与现有 anaconda 环境一致、交付即打开、响应式用 flex/grid + CSS 变量；桌面优先）。若你更想要组件化，备选 Vue3+Vite，接口契约不变。
- 后端：FastAPI + uvicorn（anaconda 环境已有）。
- 数据加载：启动时把 movies_core.json（2.3MB）读入内存 dict，查询 O(1)；FTS 用 sqlite 连接池只读；similarity.json 读入内存。
- LLM：统一 `chat_llm()` 封装，读 `data/task/llm_config.json`（provider/base_url/api_key/models 一行可换），失败/超时自动降级离线模式（B4）。

## 6. API 契约草案（前端按此编程，确认后定稿）

```text
GET  /api/movies                      列表：region/genre/year_min/year_max/rating_min/
                                      dna_dim/dna_min/tags/sort/page/limit
GET  /api/movies/{id}                 详情（富字段为 null 表示 P2 未加工，前端走降级）
GET  /api/search?q=&type=all|title|fts  搜索：标题模糊 + FTS 评论命中（返回评论片段+votes）
POST /api/auth/guest                  {device_id}            -> 游客虚账号
POST /api/auth/sms                    {phone}                -> 演示期发固定码
POST /api/auth/register               {phone,code,password,device_id} -> 注册+合并游客
POST /api/auth/login                  {phone,password|code}  -> token
GET  /api/account                     资料/收藏/历史
POST /api/chat                        {message, device_id}   -> {reply, offline:bool, citations:[…]}
GET  /api/movie-lookup?title=         库外电影轻查询（movies_info_clean 检索库，P2 聊天用）
```

**数据契约**：字段名/类型以 Phase-D 方案 v1 §2 schema 为准（HTTP 级定稿，不改名）；前端只消费 movies_core.json 的字段，不直接读 CSV。

## 8. 聊天数据链路（防幻觉关键路径）

1. 用户输入 → 意图规则分类（推荐词 / 电影名 / 检索词）。
2. 程序检索：`推荐` → DNA+similarity 规则选 590 库内片；`问答` → 命中 movie → 取 core 卡片字段；`检索` → FTS 命中评论原文。
3. 组装上下文：只放该片自家数据（卡片字段 + 评论原文 + votes），**LLM 不新增事实**。
4. LLM（可选）仅润色为自然语言；输出中的引用由程序渲染为卡片（原文 + votes + 电影链接）。
5. 任一环节失败（无 key/超时/解析失败）→ 直接返回第 3 步的规则版回复并标注"离线模式"。
